Purpose: suggest likely prerequisites from task titles and descriptions. In my design the AI proposes, deterministic checks validate, a human approves, and the DAG engine stays authoritative.

Pipeline: Propose, Challenge, Verify, then Human.
1. Propose. One batched call. The prompt holds a closed list of board tasks with numeric ids, titles and descriptions, and the model may only answer with those ids. The system prompt states delivery ordering logic (design before build, build before test, test before release), gives two worked examples, sets temperature to zero, and says that returning nothing is valid when unsure. Output is strict JSON: prerequisite id, dependent id, one sentence reason, an evidence phrase copied from the task text, and confidence.
2. Challenge. One more batched call with a skeptic prompt reviews all proposed links and argues against each: is the direction reversed, is it only a topical link and not a true finish to start dependency, could the tasks run in parallel. Failed links are dropped and doubtful ones are marked contested. This pass specifically targets reversed direction and false topical relationships. If the call fails, suggestions are still shown, marked unchallenged.
3. Verify. Deterministic checks: schema, ids exist, no self link, no duplicate, evidence phrase literally present in the task text, confidence threshold, and the engine cycle check. A suggestion that would create a cycle is dropped and logged, never offered. Evidence gives the reviewer a reason to look, not proof.
4. Human. Survivors appear as dashed ghost links with reason, evidence and a contested badge where relevant. The user accepts or rejects each. Accept uses the same dependency endpoint as a manual link, so the AI has no special write path. Rejected pairs are stored and excluded from later suggestions on that board.
5. Measure. On a hand labelled seeded graph I record raw counts of correct, wrong and missed links plus the acceptance rate, and derive precision and recall from them.
6. Failure handling. 12 second timeout, one retry on bad JSON, then a keyword heuristic fallback (schema before API before tests) labelled as heuristic. The board works fully without an LLM.
